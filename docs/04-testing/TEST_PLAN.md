## 评测标准（三层）

1. **正确性标准（客观真相 = 数据库直查值）**：L1 的金牌不是人写的，是「直查 SQL 真值」（每次复标，防 ETL 漂移）——答案对不对，以数据库为准。这是取数 Agent 最本质、也最客观的标准；比 Spider / BIRD 的金牌更客观（后者是人标注、多解、有歧义）。
2. **业界对标标准（测 SQL 子任务）**：L2 Spider / BIRD 子集，证明 SQL 生成准确率至少对齐业界基线（附诚实污染声明）。
3. **A/B 对照标准（测「我们的设计是否有效」）**：交付闸门开 / 关、有口径 / 无口径、自纠开 / 关——用 A/B 证明机制真的提升通过率、降低错误（comet Verifier A/B、daw 换模型 n=3、pi with/without docs 同一路子）。

**诚实边界**：没有真实业务库，就无法验证「真实业务口径」的对错；L1 证明的是「给定数据 + 给定口径下，agent 正确、守纪律、被闸门兜底」，**不是**「在你的真实业务上一定对」——这个边界必须写清，不能含糊。

## 测试策略

1. **单元测试**：每个守卫配 fail-loud 测试（禁词词边界、裸引远端、值域 / 关系守卫解析器）；用例取自真实翻车原文（多行 / CTE / 中文过滤值）。
2. **L1 业务口径集**（重点）：数字命中 / 来源标注 / 首句先答 / 口径正确 / 闸门红灯。
3. **L2 Spider / BIRD 子集**：SQL 执行准确率回归，附诚实污染声明——Spider 已落地：dev 前 50 题 **74%**（`deepseek-flash`，四招修复：主外键 / 查值 / 约束输出 / 自检），见 [EVAL_REPORT.md](EVAL_REPORT.md)。
4. **A/B 对照**：闸门 / 口径 / 自纠 开-关。
5. **确定性**：无 API key 跳过 LLM 用例；评测只读闸门（`eval-` 任务写工具全拒）。
