## 二、V2 分层计划

### V2.0a 度量基线（P0，最先行）

> 先建"度量尺"：后面每步改动都有对照，不凭感觉。基线必须确定性（同会话两次打分一致），LLM 打分只作语义辅助、不做基线。

| 项 | 动作 | 验收 |
|---|---|---|
| 确定性打分基线 | session_score 用机械检查（D1 交付形态 / D2 效率 / D3 知识行为 / D4 验证倾向 / D5 用户验收）做基线 | 同会话两次打分结果一致 |

### V2.0b 数据地基 + 可靠性（P0）

| 项 | 动作 | 验收 |
|---|---|---|
| TPC-H 数据集 | DuckDB `tpch` 扩展生成（默认 sf=0.01：lineitem 6 万行；sf 可调，见 `scripts/gen_tpch.py`）替代 7 行示例 | 能查真实星型数据、多表 JOIN |
| db 层 | 连接管理 + `SET TimeZone` + 多表 schema 探查 | 同 SQL 两次同数 |
| **table_registry** | 表登记（有哪些表 / 怎么访问），换数据源 / 连远程靠它 | 能列出数据源的表 |
| 工具 P0 | `sample_data`（看样例）+ `list_connections`（数据源列表） | 取数前能看真实样例 |
| fail-loud | react.py 工具异常结构化（错误类型 + 消息） | 失败有错误类型 |
| 知识库 | store.py 板块级 upsert（frontmatter 拒写 / 同名标题剥壳 / 空白归一化） | 误用不损坏知识库 |
