# 项目概览：这个 Agent 能帮你做什么（用户视角）

> 文档编号：01-requirements / PROJECT_OVERVIEW · 版本 v0.1 · 2026-11-22 · 状态：Draft
> 本文用大白话讲清楚：你打开它、跟它聊天，它能帮你干什么。不涉及技术实现。

## 一句话

它是一个**「数据小助手」**——你像问同事一样用大白话问它业务数据（销量、订单、业绩），它自己去找表、写查询、算数字，把结果连同「这个数怎么来的、意味着什么」一起告诉你，而且**越用越懂你**。

## 它到底有什么用（配例子）

### 1. 大白话问数，不用懂 SQL

你不用知道表叫什么、字段叫什么、SQL 怎么写。

> 你问：「这个月华东区卖了多少？」
> 它答：「华东区 11 月有效订单 **1,234 单**、金额 **5,678 万**。」

### 2. 先跟你确认「口径」，不瞎猜

同样一句"销量"，不同人可能指不同的数（含不含退单、含不含测试单）。它会先问清楚，而不是默默猜一个。

> 你问：「销量多少？」
> 它问：「你要的是**有效成交**（剔除退单和测试单），还是**全量订单**？」
> 你确认一次，它就记住，下次直接按这个口径算。

### 3. 数字都带「出处」，能直接拿去开会

每个关键数字后面都跟着「来自哪张表、按什么口径算的」，还顺手帮你拆维度（按区域、按产品线）。你能直接复制进周报、拿去汇报。

> 它答：「11 月有效订单 1,234 单。**来源**：订单表 `dw_order`，口径 = 剔除测试单 + 已支付。按区域拆分：华东 520、华南 400、华北 314。」

### 4. 复杂问题它自己拆开、一步步算

问"对比""同比""谁下滑了"这类要算好几步的问题，它自己拆解、自己算，最后给你结论。

> 你问：「对比各区域今年和去年的业绩，看看谁跌了。」
> 它先取今年、再取去年、再算同比、再找下滑区域，最后给一张对比表 + 一句：「华东同比 **-12%**，主要是 Q3 三个大客户流失。」

### 5. 算错了它会自己纠，不把错的交给你

它有一道"出厂质检"：数字跟它自己掌握的业务规则对不上，就自动重查纠正；实在纠不完，会老实说"这里我拿不准，需要你确认"，**不会糊弄你**。

> 它差点把「武汉咨询部」当作战区来归因，但它的规则知道"部门 ≠ 战区"，于是自动拦下、重新按正确层级算了一遍。

### 6. 不光给数，还告诉你「该怎么办」

它不只是"报数机器"，还能帮你判断：这个数意味着什么、值不值得动手。

> 你问：「最近销量为什么跌了？」
> 它答：「下滑 12%，主因是华东 Q3 流失 3 个大客户（依据：订单表近 3 个月数据）。**建议**：优先跟进这 3 家，预计可挽回 X 万。要不要我拉一份这三家的历史明细？」

### 7. 越用越懂你

你纠正过的东西、确认过的口径，它会沉淀下来。下次换种问法，它直接按你的习惯来。

> 第一次：「有效单要排除测试单」——它记下。
> 第二次你问「这个月业绩」，它直接按"排除测试单"的口径算，不再问你。

### 8. 数据在你本地，只读、不外传

它连的是**你自己的数据库**，而且**只读**（不会改你的数据）；学到的业务知识存在你机器上。最终打包成桌面软件，双击就能用。

## 它不是什么（边界，说清楚）

- **不是万能 AI**：它专精"查数、算数、看数、给建议"，不写诗、不画画、不闲聊。
- **不是"给你一个没来源的数字"**：给数必带出处和口径，没有出处的数字 = 不可信的数字。
- **不是"替你下最终决策"**：它给建议和影响评估，但拍板的是你。

## 一句话总结

把它当成**一个懂业务、会写 SQL、还知道数字对不对的数据同事**：你用大白话跟它要数，它给你能直接拿去用的答案——带出处、带口径、带结构、带建议，而且越用越顺手。
