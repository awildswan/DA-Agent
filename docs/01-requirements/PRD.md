## 1. 产品目标

一个**数据分析 Agent**——用户用大白话问业务数据，Agent 自己找表、写 SQL、算数字，返回带出处、带口径、带结构、带建议的答案，且只读、越用越懂。

- 用户视角：见 [PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md)
- 设计原则：见 [../02-design/DESIGN_PRINCIPLES.md](../02-design/DESIGN_PRINCIPLES.md)
- 系统架构：见 [../02-design/ARCHITECTURE.md](../02-design/ARCHITECTURE.md)

## 2. 目标用户

| 用户 | 痛点 | 我们的解法 |
|---|---|---|
| 业务人员 / 数据分析者 | 要数据但不会 SQL，找数据团队排队 | 大白话直接取数 |
| 数据团队 | 80% 时间在回答重复取数需求 | 让业务自助 |

## 3. 核心场景（引用）

8 个场景已写在 [PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md)：大白话问数 / 先确认口径 / 数字带出处 / 复杂问题拆解 / 算错自纠 / 给"该怎么办" / 越用越懂 / 本地只读。此处不重复。

**边界**（同样引用）：不是万能 AI；不给没来源的数字；不替用户下最终决策。

## 5. 验收标准（每功能"怎么算做对"）

> 对齐评测标准：L1 自制业务口径集（数字命中 / 来源标注 / 首句先答 / 口径正确 / 闸门红灯）、L2 Spider/BIRD 子集（SQL 准确率）、A/B 对照（机制有效性）。详见 [../04-testing/TEST_PLAN.md](../04-testing/TEST_PLAN.md)。

| 功能 | 验收标准（可测） | 对齐 |
|---|---|---|
| 单跳取数 | 问「华东 11 月订单量」→ 首句先答数字 + 数字正确 + 来源表标注 | L1 |
| SQL 只读执行 | `DROP/DELETE/UPDATE/ALTER` 全被拦截；`is_deleted` 列名不误伤 | 单测 |
| 穷尽探查 | 新数据源首连时穷尽找表，不直接说「没有订单表」；权限被拒 ≠ 不存在 | L1 |
| 交付闸门 | 故意埋的错（部门 ≠ 战区、只报 GMV 不披露放款）被红灯拦截 | L1 + A/B |
| 自纠环 | 红灯后 in-context 自纠 ≤2 轮，数字与核对 SQL 真值一致；纠不完如实披露 | L1 |
| 语义映射 | 先给业务理解 + 口径再取数；用户确认后立即沉淀 | L1 |
| 知识沉淀 | 跨会话：会话 A 沉淀口径 → 会话 B 召回并按口径交付（不再问） | L1 |
| SQL 生成能力 | Spider / BIRD 子集执行准确率对齐基线（附污染声明） | L2 |
| 业务诊断 | 问「销量为什么跌」→ 先给数字，再给归因（标注依据）+ 建议 + 影响 | L1 |
| 评测只读 | `eval-` 任务写工具全拒，评测 run 前后 OKF 仓库 HEAD 一致 | 单测 |

## 6. 非功能需求

- **只读安全**：只读账号兜底、危险操作拦截、行级权限、敏感列脱敏、防 prompt injection（作为已知风险写明）。
- **本地优先**：数据全在本机（SQLite + DuckDB + OKF git），凭据走 `.env` 不进仓库。
- **性能**：查询超时 + `queryRowLimit` + 并发控制；模型失败降级转人工。
- **可观测**：每环节打 span（OTel 风格），出错可回放定位到具体环节。
