# 设计原则（DESIGN_PRINCIPLES）

> 编号：02-design/DESIGN_PRINCIPLES · 版本 v0.1 · 2026-11-22 · 状态：Draft
> 对齐 daw 六原则；每条原则的落地机制见 [MODULE_DESIGN.md](MODULE_DESIGN.md) 对应环节。

| # | daw 原则 | 我们的落地 | 取舍 |
|---|---|---|---|
| ① | 唯一真相 | 口径先行；关键数字至少两条独立路径互证；对不上 → 诊断查询定位到数据，定位不了如实说「未定位」 | 照搬 |
| ② | 语义映射本职 | 先给业务理解再给数字；穷尽探查才说「没有」；确认后映射立即沉淀（OKF concepts / tables） | 照搬 |
| ③ | 交付纪律 | 先答所问（数字第一句）；数字带出处（业务叫法 + 物理表名 + 口径）；默认报有效口径；报数带业务结构；允许估算标注成分 | 照搬 |
| ④ | 知识地基 | OKF 知识库 git 版本化；写入守卫；**修正优先于并存**（grep 全库清零） | 照搬 |
| ⑤ | 越用越懂 + fail-loud | 沉淀 → 召回 → 按沉淀交付三步闭环；外部副作用检查结果；复盘工具是产品一部分 | 照搬 |
| ⑥ | 商业模型与全局视角 | **业务诊断与决策辅助**：结果意味着什么 → 是否值得采取措施 → 结合业务背景给建议并评估影响（标注依据） | **强化**（由轻量升级，见 ⑩） |
